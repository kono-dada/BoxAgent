# 伙伴与聊天显示屏

在聊天框右上角点击显示器图标，选择 `副屏 · 显示器名称`。
也可以从菜单栏图标的「伙伴与聊天显示屏」，或伙伴控制台「设置 → 语音与桌面 → 伙伴与聊天显示屏」选择。

- 选择一块屏幕后，伙伴、聊天和任务展示都放在所选屏幕，新消息展开也留在该屏。
- 伙伴与聊天可各自调整位置，拖动范围限制在所选屏幕内。窄屏的任务面板采用纵向排列，空间不足时作为浮层，避免窗口伸到其他屏幕。
- 指定显示器时给人物和内容窗口预留互不重叠的区域：宽屏左右排，窄屏上下排，聊天展开、任务弹出及拖动不覆盖人物。屏幕不足时只限制实际显示大小，不覆盖用户保存的缩放比例。收起聊天后保留分区，避免下次展开把人物推走。
- 聊天宽度随人物可见大小在可读范围内调整，并受屏幕工作区限制；上下排列时聊天高度不超过屏幕的一半（受最小可用高度约束），正文滚动，避免长消息挤掉人物。
- 选择「随拖动切换屏幕」恢复联动布局，并回到主屏；随后拖动整组可跨屏。
- 选择保存在本机数据目录 `display.json`，重启保留；副屏断开时临时回到主屏，同一显示器重新接入后自动恢复。
- 同时保存显示器编号和名称。重启或重连导致编号变化时，按唯一匹配的名称找回所选屏幕；若同名设备有多台且原编号不再匹配，则回到主屏，需重新选择，不猜测目标。旧配置的编号仍有效时会自动补记名称。
- 屏幕必须使用扩展模式。镜像模式不能将不同内容分别放在两块屏幕上。
- 独立显示模式按人物实际可见区域适配大小，不再用含透明留白的横向画布限制竖屏放大。大小仍在「设置 → 3D 形象 → 桌宠大小」调整，最大 600%；最终以全身能够放进屏幕为限。

实现只在 Electron DesktopHost 的窗口布局层，使用系统逻辑坐标和工作区，不修改 AOQ、摄像头、模型或 Python 服务。
`desktop_set_pet_display` 接收系统枚举出的字符串显示器 ID；`null` 恢复联动布局。
热插拔和工作区变更同时处理当前及正在预加载的形象，并在退出时注销监听。
渲染器首次上报可见边界后校准缩放；拖动约束使用裁剪后的窗口。窗口保留首帧边界，独立显示时额外预留固定动作边距（左右各 12%、上下各 6%，不超出原画布）。后续动作或诊断截图不再触发窗口缩放；手动缩放、切换屏幕与热插拔均从首帧边界计算，避免反复取整积累误差。虚拟渲染画布可以超出屏幕，实际人物窗口保持在屏内。大幅动作仍可能超出裁剪范围，这是固定边界策略的限制。

角色使用整屏渲染窗口绘制动作，始终鼠标穿透且不接收焦点。明确选择副屏时铺满场景背景，作为伙伴与内容展示区；在主屏或自由拖动模式下保持透明，避免覆盖工作桌面。另一人物命中窗口只在实际边界上报后接收点击，加载中保持穿透，初始窗口也显式限制为模型视口大小，避免 Electron 默认窗口尺寸遮挡桌面。

验证：`pnpm --dir web/panel test`、`pnpm --dir web/panel build`。
`desktop-displays.test.cjs` 覆盖分屏、独立拖动、通知、热插拔、旋转、缩放、换装、配置恢复及默认行为回归。

连接扩展副屏后，在 `web/panel` 运行 `pnpm exec electron tests/desktop-smoke.cjs --displays` 可进行真实双屏测试；它使用隔离的数据目录、模拟 Engine 和真实 VRM，不调用云端模型或打开麦克风/摄像头。
如需 Playwright 截图，同时设置 `BOXAGENT_PLAYWRIGHT_MODULE`（Playwright 模块路径）、`BOXAGENT_DISPLAY_SCREENSHOTS`（输出目录），并添加 `--remote-debugging-port=9224`。

2026-11-17 本机修复验收：98 项桌面测试通过；真实双屏覆盖副屏背景、主屏透明、最大缩放与聊天/任务避让。渲染失败和退出后的晚到回调不会再对已销毁窗口调用 `setBounds`；当前人物渲染失败会清理失效命中层并保留可操作的错误反馈。已安装包重开后严格签名校验通过；Jev-Mem 子进程继承缓存目录并禁写字节码，避免在 App 内新增 `__pycache__` 破坏签名。凭据读取按文件内容缓存，配置变化后失效，不关闭系统钥匙串或 Cookie 加密。
