# UI-P2 桌宠与对话小窗体验

状态：目标已明确，尚未实现。用户澄清：提出 Electron 是因为 MiraJelly 的页面效果好看，而 BoxAgent 当前 AppKit 界面很原始。Electron 是实现手段，验收看用户日常看到、操作的产品界面。

现有 `web/panel` 完成了 Engine 连接和只读上下文管理，属于 UI-P0/P1。它没有替换桌宠对话小窗，也没有完成这一体验目标。MiraJelly 是用户指定的视觉参考；本次未检查其实际页面，不把猜测的样式写成已核实参考。

优先改用户每天接触的桌宠与对话小窗：字体、间距、色彩、层次、输入区、消息布局及状态反馈形成统一风格，让角色、对话和操作状态显得自然协调。管理功能继续放在独立入口，日常陪伴界面不被轨迹、token 和调试信息占据。

推进顺序：先查看 MiraJelly 的实际界面并结合本产品提出可运行的小窗视觉稿；再把选定设计接到现有 Engine，完成文字输入、连续消息、语音状态、后台任务进度与必要授权；最后验证桌宠和小窗的透明、拖动、展开收起、焦点与键盘行为。Python Engine 与现有对话/记忆能力复用，外观改造不要求重写后端。

验收以真实窗口为准：

- 空闲、文字对话、语音连接/聆听/回复、任务执行及失败等状态有清晰且协调的呈现。
- 输入、滚动、长消息、历史恢复和小窗尺寸变化可用；等待任务时仍能继续聊天。
- 普通桌宠展示不抢焦点，对话输入可以获得焦点；拖动、快捷键与退出行为保持可用。
- 原型截图和实际接入截图覆盖主要状态，由用户判断视觉是否达到期待；仅证明 Electron 启动或管理面板能读数据不足以通过本需求。

UI-P3 的其他窗口与 UI-P4 的 Windows 支持另行定义，不作为 UI-P2 的先决条件。
