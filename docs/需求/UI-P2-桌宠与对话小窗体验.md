# UI-P2 桌宠与对话小窗体验

状态：已完成原生小窗的首轮视觉与交互优化，待用户体验反馈；仍使用 AppKit，未实现 Electron 小窗替换。用户澄清：提出 Electron 是因为 MiraJelly 的页面效果好看，而 BoxAgent 当前 AppKit 界面很原始。Electron 是实现手段，验收看用户日常看到、操作的产品界面。

现有 `web/panel` 完成了 Engine 连接和只读上下文管理，并已实现统一浅色规范，并追加交互记忆图与上下文控制台，待用户体验反馈，见 [图与控制台验收](<2026-10-12-记忆图与上下文控制台验收.md>)及 [管理面板验收](<2026-10-12-管理面板视觉改造验收.md>)。桌宠对话小窗已优化消息卡片、标题/状态、输入区、滚动跟随与控制台入口；原生宿主继续承担焦点和桌宠行为。已检查本地 MiraJelly 的设计规范、设置与记忆页源码、历史截图；证据和管理面板改造目标见 [参考评估](<2026-10-12-MiraJelly界面参考评估.md>)。

管理面板、桌宠与对话小窗共同建立字体、间距、色彩、层次、控件与状态反馈规范。管理面板通过结构化摘要、分组与详情展示上下文、记忆和时间线；对话小窗重点处理输入区、消息布局和角色状态，让角色、对话和操作状态自然协调。管理功能放在独立入口。

推进顺序：先根据参考评估建立共用视觉规范，在现有管理面板上实现并验证；再提出可运行的小窗视觉稿，接到现有 Engine，完成文字输入、连续消息、语音状态、后台任务进度与必要授权；最后验证桌宠和小窗的透明、拖动、展开收起、焦点与键盘行为。Python Engine 与现有对话/记忆能力复用，外观改造不要求重写后端。

验收以真实窗口为准：

- 空闲、文字对话、语音连接/聆听/回复、任务执行及失败等状态有清晰且协调的呈现。
- 输入、滚动、长消息、历史恢复和小窗尺寸变化可用；等待任务时仍能继续聊天。
- 普通桌宠展示不抢焦点，对话输入可以获得焦点；拖动、快捷键与退出行为保持可用。
- 原型截图和实际接入截图覆盖主要状态，由用户判断视觉是否达到期待；仅证明 Electron 启动或管理面板能读数据不足以通过本需求。

UI-P3 的其他窗口与 UI-P4 的 Windows 支持另行定义，不作为 UI-P2 的先决条件。

## 2026-10-12 首轮实施

- 宽度 392pt，空态高度 200pt，消息视口最多 240pt、总高度最多 416pt。角色名和运行状态分行，标题右侧增加控制台入口和收起按钮。
- 用户消息靠右、使用柔绿色底；伙伴回复靠左；任务/状态与授权分开呈现。消息全文可选择复制，真实文本布局测量高度，超长内容滚动查看。
- 输入区与发送按钮使用共用绿色，浅色/深色自动适配。语音、停止、允许/拒绝沿用原有操作；中文组合输入与回车行为保留。
- 小窗左下角使用带麦克风图标、底色和开关状态的「开启语音 / 结束语音」按钮；旁边显示「全双工 · ⌃⌥空格」，悬停说明可以直接说话与打断回复。连接中和关闭中明确显示进度并暂停重复点击，授权操作与文字草稿保留。
- 控制台使用字体原生字重，关闭合成字体样式，避免中文标题出现异常描边；「让伙伴更适合你」使用 500 字重。
- 流式回复复用未变化的历史卡片；首次恢复历史定位最新消息，用户向上阅读时保留滚动位置。标题空白处可拖动，小窗记住本次运行中的桌宠相对位置，并保持在屏幕可见范围。
- 阅读历史时，消息视口右下角显示「回到最新消息」向下箭头；点击后滚到底部并继续跟随流式回复。原生滚动通知驱动显隐，手动滚到底部也隐藏；短对话不显示，点击不改变草稿或输入焦点。
- 状态栏与桌宠右键菜单保留「伙伴控制台…」「新建会话…」「退出 BoxAgent」，采用原生符号图标与退出分组，移除其他重复操作；麦克风快捷键和系统编辑快捷键继续可用。
- 管理面板底部改成单行：左边设置入口，右边状态点与「已连接 / 未连接」。完整 Engine 状态保留悬停说明，去掉重复的本机说明文字。
