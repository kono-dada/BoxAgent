## 3. REQ-02 JEV 回合前判断（摘要）

> 详细设计后续写入 `REQ-02-JEV回合前判断.md`。这里先固定目标与基线，避免范围漂移。

1. **问题**（数据来自 REQ-01 §4.2，113 个回合）
   1. 每个回合都无条件做一次全量记忆召回，p50 1447 ms（语音）/ 1363 ms（文字）。
   2. `recall_timeout=0.35 s` 只包住向量检索；画像刷新等步骤不在预算内。
   3. 文字回合靠阻塞避免晚到，召回耗时直接加在首响应延迟上；语音回合不阻塞，17/72 次晚到。
2. **做法**：用户输入定稿后，**并行**发起两件事，共用一个总预算 $B$：
   1. **JEV 判断**：用 JEV Decision Model 判断本回合“是否需要记忆、需要哪类记忆（画像 / 事件 / 无）、是否属于任务委托”。它是高频、低风险的判断，正适合 JEV；不确定时按“需要记忆”处理，不额外调用大模型。
   2. **记忆召回**：照常发起，但受同一预算约束；JEV 判定“不需要”时提前取消。
   3. 超过预算的结果一律丢弃，不注入；记录在 `turn/prepare` 中。
3. **预算**：$B = 300\text{–}400\ \text{ms}$，覆盖从定稿到注入完成的整段，而不是单个步骤。
4. **验收**（与 REQ-01 基线对比）

   | 指标 | 基线 | 目标 |
   |---|---|---|
   | 回合前准备耗时 p50 | 1.4 s | ≤ 0.4 s |
   | 文字回合首响应延迟 | 含召回 1.4 s | 下降 ≥ 1 s |
   | 语音回合记忆晚到率 | 23.6% | 明显下降（归零依赖 REQ-04） |
   | 需要记忆却未注入（漏召回） | — | 抽样人工评估，不高于基线 |

5. **记录**：`turn/prepare` 事件追加 `jev={decision, confidence, ms, status}`，与已有的 `memory={status, ms, chars}` 并列。REQ-01 已预留这个位置。
6. **待确认**
   1. JEV Decision Model 是否已有适合“是否需要记忆”的判断类型，还是要新定义一个判断任务；调用延迟实测多少。
   2. 调用 TypeSafe.ai 会把用户本轮输入发送到外部服务（与现有记忆写入路径相同），需要你确认可以接受。
