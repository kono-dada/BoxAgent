# 千问实时语音 Demo：本次实际结果

本次在 MacBook 上接入北京地域的 DashScope WebSocket 实时 API，测试了 `qwen-audio-3.0-realtime-plus` 和 `qwen3.5-omni-flash-realtime`。API Key 由本地 `.env.local` 提供，该文件被 Git 忽略。

## 已完成

- 接入检查确认两个模型都能建立实时会话并接受会话配置。
- 用 macOS 系统语音合成同一句中文音频，按实时速度送入两个模型；两者都返回了中文转录、语音包和回答。单次试跑中，从客户端送完输入音频到收到首个输出语音包，Qwen-Audio 为约 1.65 秒，Omni Flash 为约 1.32 秒。这不是用户实际听到回复的延迟，也不足以代表稳定性能。
- 制作了麦克风与扬声器双向收发的最简 Demo。程序已在本机启动并连接 Qwen-Audio；接到用户开始说话事件时会清空旧回复的播放缓冲。这里没有记录到真人说话和实际插话的验证结果。
- 给两个模型注册了本地四则运算 `calculate` 工具。用“37 乘以 48”合成语音输入实测，两者都发起工具调用、取得 `1776`，并用语音回答。工具只解析算式，不执行模型提供的代码。
- 将工具改为接到调用后约 7 秒才回传，并在工具描述中告知这一等待时间。同一算式实测时，客户端均在调用后 7.00 秒回传工具结果。未加会话提示词时，这两次试跑中均未观察到等待期间的额外口头反馈。
- 随后加入会话提示词：耗时工具调用前，先用简短语音说明正在处理及预计等待时间；结果返回前不猜答案，也不宣称完成。加提示词后的合成音频试跑里，Qwen-Audio 说“我将开始计算，预计需要等待约 7 秒”；Omni Flash 说“好的，正在计算37乘以48的结果。请稍等，大约需要7秒。”两者都在工具结果返回后才报出 `1776`。

## 事件顺序与结论边界

在加提示词后的试跑中，Qwen-Audio 的工具调用事件比首个语音包早约 0.01 秒；Omni Flash 的首个语音包先于工具调用事件。因此，这些样本支持“先向用户提醒、再给结果”的体验，但不能证明提示词能严格保证“先说完、再发起工具调用”。

以上语音内容测试使用的是 macOS 合成音频，且每种条件只试了少量样本。尚未从本次对话中得到真人麦克风对话、实际听感、插话成功率、外放回声或费用方面的结论。
